# Mac Cleaner GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `Mac Cleaner.app`, a native SwiftUI app for non-developers that exposes all 7 features of `mac-cleaner.command`, by turning the script into a non-interactive engine the app drives. The CLI keeps working unchanged.

**Architecture:** `mac-cleaner.command` gains `--engine <command>`. It prints `@@`-prefixed, TAB-separated records and never prompts. Each interactive menu is split into a *scan* function and a *run* function, shared by the CLI menu and the engine. The SwiftUI app bundles the script, spawns it in its own process group, parses records into models, and owns every confirmation.

**Tech Stack:** `/bin/bash` 3.2, Swift 6.4 toolchain (Command Line Tools only, no Xcode), SwiftPM, SwiftUI/AppKit (macOS 13+), and Swift Testing. Tests use plain bash with stubs. There are no third-party dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-gui-design.md`

## Global Constraints

- Script stays `/bin/bash` 3.2 compatible. Forbidden: associative arrays, `mapfile`/`readarray`, `${var,,}`, `|&`, `;&`, negative array indexes.
- CLI behaviour and output stay identical. That covers the menus, `--dry-run`, `--lang` and `--help` text. `--engine` is a hidden option and is not added to `usage`. The one accepted difference is TTY-only progress text, which changes format to `[i/total] text`.
- One version source: `VERSION=` in `mac-cleaner.command`. It becomes `2.0.0` in Task 16. `build.sh` reads it from there.
- App name `Mac Cleaner`, executable `MacCleaner`, bundle id `io.github.ahmadrio.mac-cleaner`.
- macOS minimum 13.0 (`LSMinimumSystemVersion`). Builds are arm64 only (`swift build -c release --arch arm64`).
- No third-party code (Swift packages, Homebrew formulae, scripts).
- Every user-facing string is bilingual, written as `L "Indonesia" "English"` in bash and `L("Indonesia", "English")` in Swift. Bahasa Indonesia uses correct spelling.
- Nothing destructive runs without a confirmation in the app. Typed confirmation words:
  - Docker volumes and "remove everything unused": `L("HAPUS", "DELETE")`.
  - Docker wipe and OrbStack reset: `RESET`.
- Swift tests use Swift Testing (`import Testing`, `@Test`, `#expect`). XCTest isn't in the Command Line Tools.
- `Package.swift`: `// swift-tools-version: 6.0` with `swiftLanguageModes: [.v5]`.
- Global CLI options always come **before** `--engine`. Everything after `--engine` is the command and its arguments. The app calls `bash <script> --lang <id|en> [--dry-run] --engine <command> [args…]`.
- Commits: one or more per task on branch `feature/gui`. Use the repo's message style ("Add …", "Engine: …"). End each message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Engine Protocol Reference (single source of truth for Tasks 2–9)

**Records.** One per stdout line. Fields are TAB-separated. Inside a field, `emit` replaces TAB and newline with a space. A line that doesn't start with `@@` is raw tool output, and the parser yields `.plain`. stderr lines are captured as `.stderr`.

| Record | Fields |
|---|---|
| `@@progress` | text [, step, total] |
| `@@log` | level (`info` `ok` `warn` `err` `say`), text |
| `@@meta` | key, value |
| `@@row` | kind, fields… (see table below) |
| `@@freed` | kb (integer; `0` in dry-run) |
| `@@disk` | total_kb, free_kb |
| `@@error` | code, text |

Error codes: `interactive`, `unknown_command`, `bad_args`, `not_allowed`, `running`, `finder_denied`, `docker_missing`, `docker_not_ready`, `cancelled`. The Swift side adds one more, `not_found`, for when the script or a demo fixture is missing; the engine never emits it.

**Row kinds.**

| kind | fields (in order) | emitted by |
|---|---|---|
| `cache` | id, kb, kind (`safe`/`heavy`/`permanent`), label | `caches-scan` |
| `dir` | kb, path | `bigdata-scan` |
| `memapp` | kb, path, name, note, host (`0`/`1`) | `ram-scan` |
| `memproc` | kb, path, note | `ram-scan` |
| `app` | kb, days (`-1` = never recorded), rare (`0`/`1`), name, path | `apps-scan` |
| `appname` | name, path | `apps-list` |
| `leftover` | kb, path | `uninstall-plan` |
| `admin` | path | `uninstall-plan` |
| `df` | type, total, active, size, reclaimable | `docker-status` |
| `container` | id, state, size, name, image | `docker-list containers` |
| `image` | ref, size, created, status (`in_use`/`unused`/`dangling`) | `docker-list images` |
| `volume` | name, links, size, used_by | `docker-list volumes` |
| `update` | kind (`formula`/`cask`/`dmg`/`sparkle`/`mas`), name, from, to, via, ref, app, homepage | `updates-scan` |

**Meta keys.**

| command | keys |
|---|---|
| `env` | `version`, `lang`, `dry_run`, `has_brew`, `has_docker`, `has_orb`, `has_mas`, `has_fda` |
| `caches-scan` | `total_safe`, `total_heavy` |
| `bigdata-scan` | `fda` |
| `ram-scan` | `total`, `app`, `wired`, `comp`, `cached`, `used`, `swap`, `level` |
| `ram-purge` | `cached_before`, `cached_after` |
| `apps-scan` | `total`, `rare_n`, `rare_kb` |
| `uninstall-plan` | `name`, `bundle_id`, `app_kb`, `dup` (path or empty), `vendor_hint` (`0`/`1`) |
| `docker-status` | `state` (`missing`/`stopped_orb`/`stopped_desktop`/`stopped_other`/`running`), `engine` (`Docker`/`OrbStack`), `containers`, `running`, `images`, `volumes` |
| `updates-scan` | `has_brew`, `pinned`, `auto_skip`, `mas_n`, `has_mas`, `offline` |

**Commands.** A wrong or missing argument gives `@@error bad_args` and exit 2. An unknown command gives `@@error unknown_command` and exit 2.

`env` · `disk` · `set-lang <id|en>` · `caches-scan` · `caches-clean <id>…` · `bigdata-scan` · `ram-scan` · `ram-purge` · `apps-scan <days>` · `apps-list` · `uninstall-plan <app>` · `uninstall <app> --list <file>` · `docker-status` · `docker-start` · `docker-list <containers|images|volumes>` · `docker-rm <containers|images|volumes> --list <file>` · `docker-prune <images-unused|images-dangling|build-all|build-old|networks|safe|all-unused|wipe|orb-reset>` · `updates-scan` · `updates-apply --list <file>` · `_probe-confirm` (test hook: calls `confirm`)

**List files (`--list <file>`).** UTF-8, one item per line, blank lines ignored.
- `uninstall`: absolute leftover paths. An empty file means the app only.
- `docker-rm`: container ids, image refs or volume names.
- `updates-apply`: TAB-separated `kind, name, from, to, ref, app, homepage`. These are the `update` row fields minus `via`.

**Environment variables.**
- `MAC_CLEANER_APP`: bundle path of the running app. It is excluded from every app list.
- `MAC_CLEANER_APP_DIRS`: colon-separated override of `/Applications:$HOME/Applications` (tests).
- `MAC_CLEANER_TRASH=home`: `move_to_trash` uses `mv_to_home_trash` (tests).
- `MAC_CLEANER_SCRIPT`: Swift dev override for the script location.
- `MAC_CLEANER_DEMO=1`: the Swift app replays fixtures instead of spawning the script.

## Review Focus

1. **Paths with spaces, `&`, apostrophes or non-ASCII** (`Café Notes.app`, `~/Library/Application Support/Café Notes`). They must round-trip unchanged through rows and `--list` files and land in the Trash. Pinned by `test_uninstall_unicode_names` (Task 5) and `listFileRoundTrip` (Task 8).
2. **Finder automation denied (-1743).** Nothing is moved and `@@error finder_denied` is emitted. There is no silent `mv` fallback. The screen shows the Automation callout. Pinned by `test_caches_clean_trash_finder_denied` (Task 3), `test_uninstall_finder_denied` (Task 5) and `finderDeniedIsExposed` (Task 10).
3. **Nothing found** (bare HOME, no containers, no updates). The engine exits 0 with zero rows, and each screen shows an empty state, not a blank table. Pinned by `test_caches_scan_empty_home` (Task 3), `test_docker_list_empty` (Task 6) and `emptyScanEndsDone` (Task 10).
4. **The engine fails or can't be found** (non-zero exit, `@@error`, no script). The screen ends in a failed state with a message and a retry, never a stuck spinner. Pinned by `exitCodeIsDelivered` (Task 9) and `nonZeroExitFails` (Task 10).
5. **The user leaves a screen or quits the app while a job runs.** Scans are cancelled with the whole process group. Running actions block quit with an alert until they finish, and Cancel is never offered during an action. Pinned by `cancelKillsProcessGroup` (Task 9) and `cancelOnlyWhileScanning` (Task 10).

## Phase B: Engine mode in `mac-cleaner.command`

Test harness used by every engine task (created in Task 2):
- `tests/lib.sh` provides:
  - `mk_home`: sets `T_HOME` to a fresh temp dir and `T_BIN` to an empty stub dir.
  - `mkfile <path> <kb>`: `mkdir -p` the parent, then `dd if=/dev/zero bs=1024 count=<kb>`.
  - `stub <name> <body>`: writes an executable to `$T_BIN/<name>` that appends `"<name> $*"` to `$T_BIN/calls.log` and then runs `<body>`.
  - `engine <args…>`: runs `env HOME="$T_HOME" PATH="$T_BIN:$PATH" MAC_CLEANER_APP_DIRS="$T_HOME/Applications" MAC_CLEANER_TRASH=home /bin/bash "$SCRIPT" --lang en "$@" </dev/null`. It sets `OUT`, `ERR` and `RC`.
  - `engine_finder <args…>`: the same as `engine`, but without `MAC_CLEANER_TRASH`, so the Finder path (`osa_finder`) is used. Only use it together with an `osascript` stub, so nothing reaches the real Trash.
  - Assertions: `assert_rc`, `assert_line <ERE>` / `assert_no_line <ERE>` (against `$OUT`), `assert_protocol`, `assert_exists`, `assert_missing`, `assert_called <ERE>`, `assert_not_called <ERE>`.
  - `assert_protocol` checks that every line starting with `@@` matches `^@@(progress|log|meta|row|freed|disk|error)\t`.
- `tests/engine_test.sh` sources `lib.sh` and every `tests/engine/*.sh`, runs each `test_*` function in a subshell, prints `ok`/`FAIL name`, and exits non-zero if any test failed. Run it with `bash tests/engine_test.sh`.
- `tests/cli_regression.sh` (created in Task 3) compares old and new CLI output. It does the following:
  1. Builds a fixture HOME.
  2. Writes `git show 6ecf5ce:mac-cleaner.command` to a temp file.
  3. Runs old and new with `--lang en --dry-run` and the same stdin, for each case in its `CASES` array.
  4. Prints `diff -u` on mismatch and exits 1.
